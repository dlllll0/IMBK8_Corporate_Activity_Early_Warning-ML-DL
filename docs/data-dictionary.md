# 비공개 데이터 입력과 실행 조건

이 저장소에는 실데이터가 없습니다. 아래는 자료 구조와 코드 실행 조건이며 재배포 허가나 사용권을 부여하는 문서가 아닙니다.

## 1. 법인 데이터 `corp.csv`

UTF-8 CSV, 원본 70열. 한 행은 법인·월 관측입니다. 동일 법인·월 중복은 원본 코드대로 마지막 행을 선택합니다. 월 범위는 202301–202512입니다.

| 변수/분류 | 형식 | 사용 |
|---|---|---|
| `법인ID` | 비공개 문자열 | 동일 익명 법인의 월별 연결용; 원본·변환값 모두 공개하지 않음 |
| `기준년월` | YYYYMM | 시간 순서·분할·다음 달 라벨 연결 |
| `업종_대분류`, `업종_중분류` | 범주형 | 업종 선별·외부 변수 결합 |
| `사업장_시도`, `사업장_시군구` | 범주형 | 지역 설명·감성지수 결합 |
| 6개 채널 거래건수 | `0건`, `10건초과 20건이하` 등의 구간 문자열 | 목표값 정의; 구간 예시는 입력 형식 설명이며 실제 행이 아님 |
| 예금·여신 잔액, 거래·사용 금액 | 수치형 | 거래 규모·변동성·비중 등의 파생변수 |
| 상품 좌수·보유 개수 | 구간 문자열 | 보유·채널 이용 구조 |

추가 분석은 위 ID·월·업종과 `창구거래건수`, `인터넷뱅킹거래건수`, `스마트뱅킹거래건수`, `폰뱅킹거래건수`, `ATM거래건수`, `자동이체거래건수`만 읽습니다. 다른 61열의 행별 값은 추가 분석에 사용하지 않습니다. 원본 70열 형식인지 별도로 검사합니다.

금액의 원 단위·스케일·반올림 규칙을 추정해 바꾸지 않습니다. 실제 적용 전 제공기관의 데이터 사전을 확인해야 합니다. 이번 추가 분석은 금액을 사용하지 않습니다.

## 2. 원본 모델의 외부 입력

권한 있는 입력을 저장소 밖 한 폴더에 준비하고 아래 이름으로 배치합니다. 자료가 없으면 모델 노트북은 실행을 중단합니다. 변수만 흉내 낸 가짜 지표로 원본 성능을 재현하지 않습니다.

| 파일 | 결합 키 | 주요 필드 |
|---|---|---|
| `buzz.csv` | `업종_중분류`, `기준년월` | `버즈` |
| `macro_indicators.csv` | `기준년월` | 원본 금리·환율·거시지표 열; 예: `CD금리`, `국고채3년`, `USD_KRW` |
| `model_sentiment_index.csv` | 업종·지역·월 | 업종/지역 뉴스 수, 감성 평균·중앙값·표준편차, 긍정·부정·중립 비율, 혼합지수 |

감성 파일은 `industry` 또는 `업종_대분류`, `month` 또는 `기준년월`, `사업장_시도`를 요구합니다. 구체적인 선택 필드·결합 방식은 노트북의 원본 셀 17에 보존했습니다. 논리 보존을 위해 기존 열 선택 규칙을 유지했으므로, 임의로 만든 일부 열만 가진 파일로 얻은 결과는 원본 재현이 아닙니다.

```powershell
$env:PROJECT4_PRIVATE_DATA_DIR = "<권한 있는 입력 폴더>"
python -m pip install -r requirements-model.txt
python -m jupyterlab
```

`notebooks/01-original-model.ipynb`를 열어 위에서부터 실행합니다. 학습과 파생변수 생성에는 큰 메모리와 시간이 필요합니다. 이번 정리에서는 전체 재학습을 실행하지 않았고 구문·입력 구조만 점검했습니다. 사용자가 재실행하면 저장 출력에 내부 정보가 생길 수 있으므로 공개 전 출력 제거와 재검토가 필요합니다.

## 3. 공개 출력

`results`는 집계 지표만, `assets`는 검토한 요약 그림만 포함합니다. 집계는 실제 분석 결과이며 합성 데이터가 아닙니다. 단위는 법인 또는 법인·월을 구분합니다. 계정 정보, 식별자, 고객별 순위·점수·추천, 뉴스 본문, 모델 가중치는 포함하지 않습니다.

가상 경제성 계산은 `business-scenarios.json` 및 `persona-analysis.json`의 assumptions/hypothetical 항목에 별도로 표시했습니다. 이 항목의 비용·이익·개입 효과는 실제 집계가 아닌 가정입니다.

## 4. 고객군 사후 분석 입력

`analyze_personas.py`는 원천 `corp.csv`와 비공개 `k3_persona_base.csv`, `k3_summary.csv`를 요구합니다. 이 CSV들은 공개하지 않습니다.

- `k3_persona_base.csv`: 법인ID, cluster, n_months, y_rate, blend_score_mean, 보간행비율. 각 법인 1행, 4,507개, n_months=6을 검사합니다.
- `k3_summary.csv`: cluster, corp_count, y_rate_mean, blend_score_mean 등. 법인별 배정 집계와 대조합니다.
- 이 분석은 별도 FINAL 작업본의 저장된 군집을 재사용하며 KMeans를 다시 학습하지 않습니다. 제출본과 작업본의 모델 점수를 섞지 않습니다.

```powershell
python scripts/analyze_personas.py --input "<원천 CSV>" --personas "<비공개 k3_persona_base.csv>" --summary "<비공개 k3_summary.csv>" --output local-results/persona-recheck.json
```

출력 파일이 이미 있으면 중단합니다. 원자료·배정 파일은 읽기만 하고, 식별자나 고객별 값을 출력하지 않습니다. 거래 특성은 202509–202511의 관측 월만 사용하고 누락 월을 0으로 채우지 않습니다. 금액의 절대 단위를 확인하지 못해 안정형 대비 지수와 집단 비중만 공개합니다. 관측 월이 3개 모두 있는 법인으로 민감도도 계산합니다.

발표자료 이미지는 익명 식별자가 없는 13·15쪽만 사용했습니다. 14·16쪽의 법인ID 예시는 포함하지 않았습니다. 15쪽의 당시 표현과 코드/현재 해석의 차이는 README에 명시했습니다.

## 5. 동일 행 재검증과 업종·과거 규모 조정

`revalidate_models.py`는 비공개 원천 CSV만 사용하고, `adjust_persona_comparison.py`는 같은 원천과 비공개 `k3_persona_base.csv`를 사용합니다. 두 스크립트 모두 이미 존재하는 출력 파일을 덮어쓰지 않습니다. 전자는 추가로 LightGBM이 필요하며 로컬 확인 버전은 환경 JSON에 기록했습니다.

새 모델은 2025.05까지의 관측으로 후보를 고정합니다. 관측되지 않은 달의 건수를 0으로 채우지 않고, 현재·다음 달 대리 목표 계산에 필요한 관측이 모두 있는 평가 행에서 같은 y를 사용합니다. 원본과 같은 LightGBM 주요 하이퍼파라미터를 사용하지만, 인과 방향의 내부 거래 변수로 다시 구성한 실험이라 원본 외부지수 포함 모델과 직접 점수 차이를 비교하지 않습니다. 실제 월말 마감 자료 가용 여부는 운영 전 확인해야 합니다.

고객군 표준화는 2025.01–05의 예금·여신 합을 과거 규모의 대리 변수로 사용합니다. 업종별 5분위의 경계는 비교 기간 값을 사용하지 않고 정합니다. 2025.09–11이 모두 관측된 법인 중 각 군집에 20개 이상 있는 공통 층만 사용합니다. 이 분석은 원래 저장된 군집을 재학습하지 않으며, 시점이 겹치는 사후 비교라는 한계는 유지됩니다.

```powershell
python -m pip install lightgbm
python scripts/revalidate_models.py --input "<비공개 원천 CSV>" --output local-results/paired-recheck.json
python scripts/adjust_persona_comparison.py --input "<비공개 원천 CSV>" --personas "<비공개 군집 배정 CSV>" --output local-results/adjusted-recheck.json
```

입력 파일을 읽고 모델을 메모리에서 학습할 뿐 원본·고객별 예측·모델 가중치를 저장하거나 외부로 보내지 않습니다. 출력은 confusion matrix, 집계 지표, 포괄 범위, 부트스트랩 구간입니다.
